# Final Team Presentation

At the conclusion of the capstone project, each team will deliver a **20-minute presentation** followed by **10 minutes
of reviewer Q&A**.

The presentation should focus on demonstrating how the team addressed the business problem, applied engineering
fundamentals, and met the evaluation rubric criteria.

## Recommended Presentation Structure

### 1. Business Problem & Solution Overview (2-3 minutes)

Provide a brief overview of:

- The business problem being solved
- Key assumptions made
- High-level solution approach
- How the solution aligns with the care coordination use case

### 2. Architecture & Design Decisions (4-5 minutes)

Explain:

- Overall solution architecture
- Key system components and their responsibilities
- Data model and entity relationships
- Important design decisions and tradeoffs
- How the solution supports maintainability and scalability

Provide architecture diagrams where appropriate.

### 3. Application Demonstration (8-10 minutes)

Demonstrate the working application by showing:

- Referral creation and retrieval
- Referral status updates
- Referral filtering and search capabilities
- Overdue referral identification
- UI functionality and user workflows
- Any stretch goals or additional functionality implemented

The demonstration should highlight how the application addresses the original business problem and supports care
coordination workflows.

### 4. Engineering Quality & Operational Readiness (2-3 minutes)

Discuss:

- Testing strategy and code coverage
- CI/CD implementation
- Validation and error handling
- Logging and observability considerations
- Repository organization and documentation

### 5. Team Learnings & Reflection (1-2 minutes)

Share:

- Key challenges encountered
- Major lessons learned
- Tradeoffs made during implementation
- What the team would improve if given additional time

## Mapping to the Rubric

Teams should explicitly demonstrate how their solution satisfies the evaluation criteria, as defined in
the [rubric](final-presentation-rubric.md):

- Business Problem Understanding & Scope
- Backend Service & API Design
- Data Modeling & Synthetic Data Usage
- UI & Usability
- Engineering Quality, Testing, & Documentation

Reviewers may ask questions related to any aspect of the solution, including architecture, business rules,
implementation decisions, testing, deployment, and team collaboration.

## Presentation Expectations

- Every team member should actively contribute to the presentation.
- Demonstrations should use the deployed or running application whenever possible.
- Teams should reference evidence from their repository, documentation, tests, and application during the presentation.
- The presentation should focus on engineering decisions and outcomes rather than reading through source code.
